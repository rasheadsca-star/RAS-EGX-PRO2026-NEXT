# مخاطر التكلفة — تخزين Cloudflare R2 (للمراجعة قبل موافقة المالك)

**لا تُفعَّل أي عملية تخزين آلية قبل موافقتك.** الـworkflow يدوي فقط ويشترط متغيرين `DECISION_ROOM_ENABLED=true` و`STORAGE_OWNER_APPROVED=true`. لم ألمس الـbucket `egx-pro-central-db` ولا أملك أي مفاتيح له.

## حقائق التسعير (من صفحة Cloudflare الرسمية، تحققت منها اليوم 2026-11-02)
| | الطبقة المجانية شهريًا | ما فوقها (يُحاسَب) |
|---|---|---|
| تخزين Standard | 10 GB-شهر | $0.015 / GB-شهر |
| Class A (PUT/LIST/multipart) | 1 مليون | $4.50 / مليون |
| Class B (GET/HEAD) | 10 ملايين | $0.36 / مليون |
| Egress | مجاني | مجاني |
* **تجاوز الحد لا يوقف الخدمة — يُحاسَب.** لذلك لا نعتمد على تنبيهات الميزانية؛ الحماية هي حدود داخل الكود تُوقف التحديث قبل الوصول.
* التخزين «Infrequent Access» بلا طبقة مجانية — لا يُستخدم أبدًا. DeleteObject وAbortMultipartUpload مجانيان، لكن الكود لا يحذف شيئًا.
* لا أستطيع من هنا التحقق من إعدادات حسابك (طريقة الدفع، خطة Workers/R2 المفعلة). **تحقق أنت** أن الحساب على الخطة المجانية وأن R2 لا يحمل خطة مدفوعة.

## الضمانات في الكود (`central_store.py`، مختبرة)
1. **سقوف صلبة = 50% من الطبقة المجانية** (5 GB / 500k A / 5M B) لا يمكن رفعها بالإعدادات؛ الإعدادات تخفضها فقط. الافتراضي أشد: **3 GB / 100k A / 1M B**.
2. **إيقاف التحديث عند 80%** من أي حد (حجم أو عمليات الشهر) *قبل* كتابة أي شيء؛ القراءة تبقى مسموحة حتى 100% ثم تُمنع أيضًا.
3. كل عملية تُعدّ (A/B) وتُسجَّل في دفتر شهري داخل الـbucket؛ دفتر تالف أو غير مقروء = **فشل مغلق** (لا تشغيل).
4. ميزانية عمليات لكل تشغيل (60 A / 60 B) تمنع الحلقات الهاربة.
5. رفع بطلب PUT واحد فقط (لا multipart) وأي كائن >400MB مرفوض → لا أجزاء يتيمة تستهلك مساحة.
6. لا حذف تلقائي لأي نسخة سليمة؛ `retention-plan` تقرير فقط.

## تقدير الاستهلاك (القاعدة الحقيقية)
* القاعدة 231 MB خام ← **≈37 MB مضغوطة (gzip)**. نسخة كاملة غير قابلة للاستبدال كل جلسة.
* السقف الافتراضي 3 GB، والإيقاف عند 80% = 2.4 GB ≈ **65 نسخة ≈ 3 أشهر من التحديث اليومي** (القاعدة تكبر مع الوقت، فأقل قليلًا). بعدها **يتوقف التحديث** ولا يحذف شيئًا — يلزم قرارك.
* عمليات كل تشغيل يومي (DB + journal، قيست فعليًا على القاعدة الحقيقية محليًا) ≈ 12 Class A و≈ 28 Class B (أي ~270 A / ~620 B شهريًا) ← أقل من 0.1% من الحد المجاني.
* الخطر الحقيقي ليس العمليات بل **نمو التخزين** (لا حذف). سياسة احتفاظ مقترحة للمراجعة، **غير مفعّلة**: آخر 30 نسخة يومية + نسخة أسبوعية لمدة 6 أشهر، بحذف يدوي من المالك فقط بعد `retention-plan`.

## المخاطر المتبقية
* السباق: workflowان متزامنان قد يتجاوزان العدّاد قليلًا؛ يُمنع بـ`concurrency` في GitHub، والحد الصلب 50% يمنح هامشًا كبيرًا.
* العدّاد من جهتنا فقط؛ أي استخدام آخر للـbucket أو الحساب (وصول يدوي، أدوات أخرى) لا يظهر فيه. استخدم bucket مخصصًا ومفتاحًا مقيدًا به.
* مسار S3/R2 الحقيقي لم يُجرَّب: الاختبارات بعميل وهمي، وعميل boto3 الحقيقي فُحص بناؤه فقط (بلا اتصال). أول تشغيل يجب أن يكون يدويًا ومُراقَبًا بأمر `check-config` ثم `bootstrap`.
